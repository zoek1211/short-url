# 02: 원본 URL 검증

**What to build:** 서버가 원본 URL을 스펙의 규칙대로 검사하고, 통과하지 못하면 400과 한국어 오류 메시지를 돌려준다. 화면은 그 메시지를 입력창 아래에 보여 준다.

**Blocked by:** 01 로컬에서 생성하고 이동하기

**Status:** ready-for-agent

- [x] 앞뒤 공백을 지운 뒤 검사하고, 지운 문자열을 그대로 저장한다(정규화하지 않음)
- [x] `http`/`https`가 아닌 스킴은 400
- [x] 호스트가 없는 URL은 400
- [x] 내부에 공백이 있는 URL은 400
- [x] 사용자 정보(`user:pass@`)가 있는 URL은 400
- [x] 2048자를 넘는 URL은 400
- [x] 호스트가 공개 기본 주소나 백엔드 주소인 URL은 400. 두 주소는 환경변수로 받는다
- [x] 각 거부 사유마다 HTTP 경계 통합 테스트가 있다
- [x] 화면에서 잘못된 URL을 생성하면 입력창 아래에 오류 이유가 보인다

## Comments

- 01 리뷰에서 나온 점: 원본 URL을 그대로 `Location` 헤더에 넣으므로, 헤더에 쓸 수 없는 문자(비ASCII, 제어 문자)가 들어오면 현재는 500이 난다. 검증 단계에서 이런 입력을 400으로 거부하거나, 저장 전에 퍼센트 인코딩할지 정해야 한다. 2048자 제한도 문자 수가 아니라 바이트 기준으로 확인할 것(원본 URL UNIQUE 인덱스의 행 크기 한도와도 관련).

- 구현 메모(02): 검사 순서는 길이(바이트) → 공백/제어 문자 → 파싱(`url` crate)·스킴 → 호스트 → 사용자 정보 → 자기 주소. 스킴이 없는 입력(`example.com`)은 스킴 오류로 처리한다. 형식 파싱 자체가 실패한 그 밖의 경우는 "형식이 올바르지 않습니다" 메시지.
- 비ASCII URL은 허용한다. 저장은 원문 그대로, 리디렉션의 `Location`에는 `url` crate의 ASCII 직렬화(punycode 호스트, 퍼센트 인코딩)를 쓴다. 제어 문자는 400.
- 자기 주소 비교는 `PUBLIC_BASE_URL`과 선택 환경변수 `BACKEND_BASE_URL`의 호스트(소문자, 포트·스킴 무시). 서브도메인·후행 점(`localhost.`)·IP 별칭 등 우회는 막지 않는다.
- `https:///path`는 `url` crate(WHATWG)가 호스트 `path`로 해석하므로 통과한다(호스트 없음으로 거부하지 않음).
- 남은 점: 저장된 값이 `Location` 직렬화에 실패하면 500(검증을 통과한 값은 이론상 실패하지 않음). 화면은 기존 `.error` div로 메시지를 보여 주며 코드 변경 없음(입력창 바로 아래 위치는 코드로만 확인, 브라우저로 눈으로 확인하지 않음).
