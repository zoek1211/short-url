# 02: 원본 URL 검증

**What to build:** 서버가 원본 URL을 스펙의 규칙대로 검사하고, 통과하지 못하면 400과 한국어 오류 메시지를 돌려준다. 화면은 그 메시지를 입력창 아래에 보여 준다.

**Blocked by:** 01 로컬에서 생성하고 이동하기

**Status:** ready-for-agent

- [ ] 앞뒤 공백을 지운 뒤 검사하고, 지운 문자열을 그대로 저장한다(정규화하지 않음)
- [ ] `http`/`https`가 아닌 스킴은 400
- [ ] 호스트가 없는 URL은 400
- [ ] 내부에 공백이 있는 URL은 400
- [ ] 사용자 정보(`user:pass@`)가 있는 URL은 400
- [ ] 2048자를 넘는 URL은 400
- [ ] 호스트가 공개 기본 주소나 백엔드 주소인 URL은 400. 두 주소는 환경변수로 받는다
- [ ] 각 거부 사유마다 HTTP 경계 통합 테스트가 있다
- [ ] 화면에서 잘못된 URL을 생성하면 입력창 아래에 오류 이유가 보인다

## Comments

- 01 리뷰에서 나온 점: 원본 URL을 그대로 `Location` 헤더에 넣으므로, 헤더에 쓸 수 없는 문자(비ASCII, 제어 문자)가 들어오면 현재는 500이 난다. 검증 단계에서 이런 입력을 400으로 거부하거나, 저장 전에 퍼센트 인코딩할지 정해야 한다. 2048자 제한도 문자 수가 아니라 바이트 기준으로 확인할 것(원본 URL UNIQUE 인덱스의 행 크기 한도와도 관련).
