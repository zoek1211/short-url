# 08: README와 배포 후 점검 스크립트

**What to build:** 처음 저장소를 받은 사람이 README만 보고 서비스 규칙과 실행 방법을 알 수 있고, 운영자는 스크립트 하나로 배포된 공개 주소가 확인 시나리오를 모두 통과하는지 점검할 수 있다.

**Blocked by:** 02 원본 URL 검증, 03 같은 원본 URL 재입력과 동시 생성, 04 번호 해석과 404 안내 화면, 05 불변성, 07 Cloudflare 프록시와 화면 배포

**Status:** ready-for-agent

- [ ] README 제목은 `# 숫자형 단축 URL 서비스`이고, 바로 아래 `## 배포 URL` 섹션에 서비스 URL(Cloudflare 공개 HTTPS 주소), 테스트 단축 URL(배포한 서비스에서 실제로 만든 `/숫자` 주소), 테스트 원본 URL(그 단축 주소가 이동하는 주소)이 실제 값으로 적혀 있다. 형식은 `- 서비스 URL: ...`, `- 테스트 단축 URL: ...`, `- 테스트 원본 URL: ...` 세 줄을 그대로 쓴다
- [ ] `## 배포 URL` 아래에 로컬 실행 방법, DB 준비 방법, 필요한 환경변수 이름이 적혀 있다
- [ ] README에 Railway·Cloudflare 배포 방법과 라우팅 구성(어떤 경로가 어디로 가는지)이 적혀 있다
- [ ] README에 번호 발급 방식, 중복 방지 방법(같은 원본 URL 재입력 시 기존 번호 반환 규칙 포함), 생성 후 불변을 지키는 방법이 적혀 있다
- [ ] README에 확인 시나리오의 결과나 재현 방법이 적혀 있다
- [ ] 배포 설정 파일과 `.env.example`이 저장소에 있고, 실제 비밀 값은 들어 있지 않다
- [ ] 점검 스크립트가 공개 주소를 인자로 받아 curl로 다음을 확인한다: 생성, 프록시를 거친 `/<번호>` 302 이동, 같은 URL 재입력 시 같은 번호, 서로 다른 URL 동시 생성 시 번호 충돌 없음, 없는 번호 404, 변경 요청 405, 잘못된 URL 400
- [ ] 점검 스크립트가 배포된 공개 주소에서 모두 통과한다
- [ ] 시크릿 창과 다른 브라우저에서 생성·복사·이동을 직접 확인했다
