# 숫자형 단축 주소 서비스

Status: ready-for-agent

## Problem Statement

긴 원본 URL을 공유하기가 불편하다. 메신저나 문서에 붙이면 줄이 깨지고, 소리 내어 읽어 주거나 손으로 옮겨 적기도 어렵다. 기존 단축 서비스는 회원가입을 요구하거나, 읽기 어려운 영문·랜덤 문자열을 주소로 준다. 사용자는 로그인 없이 바로 쓸 수 있고, `/123`처럼 숫자만 들어간 짧은 주소를 원한다. 또 한 번 만든 주소는 나중에 다른 곳으로 바뀌거나 사라지지 않는다는 확신이 필요하다.

## Solution

로그인 없이 원본 URL을 입력하고 생성 버튼을 누르면 `https://<공개 주소>/<번호>` 형태의 단축 주소를 보여 주고, 버튼 하나로 복사할 수 있게 한다. 누군가 단축 주소를 열면 서버가 HTTP 리디렉션으로 원본 URL에 그대로 보낸다. 한 번 발급한 링크는 영구적이다. 수정, 삭제, 만료가 없고, 번호는 다른 원본 URL에 다시 쓰이지 않는다. 서버를 재시작하거나 재배포해도 모든 단축 주소가 같은 원본 URL로 이동한다.

화면과 공개 접점은 Cloudflare Workers에, 생성 API·리디렉션 처리·DB는 Railway에 배포한다. 사용자는 Cloudflare 공개 주소 하나만 보게 된다.

## User Stories

## Implementation Decisions

- **워크스페이스 구성**: Cargo 워크스페이스 하나에 크레이트 세 개를 둔다. `shared`는 API 요청·응답 타입, `backend`는 axum JSON API와 리디렉션 처리, `web`은 Dioxus 웹(WASM) 화면만 맡는다. Dioxus fullstack 서버 함수는 쓰지 않는다(ADR 0001).
- **Cloudflare Worker 프록시**: Dioxus 빌드 결과를 Workers 정적 파일로 올리고, 앞단에 작은 JS Worker를 둔다. 경로가 숫자로만 되어 있거나 `/api/`로 시작하면 Railway 백엔드로 넘기고, 백엔드 응답(302 포함)을 수정하지 않고 그대로 브라우저에 전달한다. 리디렉션을 따라가지 않도록 프록시 요청은 수동 리디렉션 모드로 보낸다. 나머지 경로는 Dioxus 화면을 내준다. 백엔드 주소는 Worker 환경변수로 받는다.
- **같은 출처 API**: 브라우저는 공개 주소의 `/api/*`만 호출한다. CORS 설정은 두지 않는다.
- **API 계약**:
  - 생성: 링크 생성 엔드포인트에 `url` 필드 하나만 있는 JSON을 POST한다. 알 수 없는 필드가 있으면 400. 성공하면 번호, 단축 주소, 기존 링크인지 여부를 돌려준다. 새로 만들었으면 201, 기존 링크를 돌려주면 200.
  - 검증 실패는 400과 사람이 읽을 수 있는 한국어 오류 메시지를 돌려준다.
  - 링크 하나를 가리키는 API 경로와 `/<번호>`에 GET이 아닌 메서드가 오면 405.
- **리디렉션**: `/<번호>`는 302와 저장된 원본 URL을 그대로 담은 `Location`을 돌려준다. 단축 주소에 붙은 쿼리는 무시한다. 프래그먼트는 서버에 오지 않으므로 별도로 처리하지 않는다.
- **번호 해석**: 0으로 시작하지 않는 양의 정수이면서 DB 정수 범위 안에 있어야 번호로 인정한다. 그 밖의 숫자 경로와 존재하지 않는 번호는 백엔드가 만든 한국어 404 HTML을 404 상태로 돌려준다.
- **원본 URL 검증**: 앞뒤 공백을 지운 뒤 다음을 모두 만족해야 한다.
  - 스킴이 `http` 또는 `https`
  - 호스트가 있음
  - 내부에 공백이 없음
  - 사용자 정보(`user:pass@`)가 없음
  - 2048자 이하
  - 호스트가 공개 주소나 백엔드 주소가 아님
  - 정규화하지 않는다. 공백을 지운 문자열을 그대로 저장하고 비교한다.
- **DB 스키마**: Railway Postgres에 링크 테이블 하나를 둔다. 번호는 `BIGINT GENERATED ALWAYS AS IDENTITY` 기본키이고, 원본 URL은 UNIQUE이며 생성 시각을 함께 저장한다. 번호 사이에 빈자리가 생기는 것은 허용한다.
- **생성과 중복 처리**: 삽입 시 원본 URL 충돌이 나면 아무것도 하지 않고, 기존 행의 번호를 조회해 돌려준다. 같은 URL로 동시에 요청이 와도 번호는 하나만 생긴다.
- **불변성**: 수정·삭제 경로를 만들지 않는다. DB 트리거로 링크 테이블의 UPDATE, DELETE, TRUNCATE를 모두 거부한다.
- **마이그레이션**: 백엔드가 시작할 때 `sqlx` 마이그레이션을 실행한다.
- **설정**: 백엔드는 DB 접속 주소, 공개 기본 주소, 백엔드 자신의 주소, 수신 포트를 환경변수로 받는다. 공개 기본 주소의 기본값은 `http://localhost:8080`이다. 비밀 값은 Railway와 Cloudflare 설정, GitHub Secrets에만 둔다.
- **화면 동작**: 생성에 성공하면 입력창 아래에 단축 주소와 복사 버튼을 보여 주고, 실패하면 같은 자리에 오류 메시지를 보여 준다. 기존 링크를 돌려받은 경우 안내 문구를 덧붙인다.
- **배포**: 공개 GitHub 저장소를 쓴다. Railway는 저장소와 연결해 Dockerfile로 백엔드를 자동 빌드·배포한다. Cloudflare는 GitHub Actions에서 Dioxus 화면을 빌드하고 `wrangler deploy`로 올린다. 공개 주소는 `*.workers.dev`이며, Railway 주소로 직접 들어오는 요청은 막지 않는다.

## Testing Decisions

- **좋은 테스트의 기준**: 외부에서 관찰할 수 있는 동작만 검증한다. HTTP 상태 코드, 헤더, 응답 본문, DB에 남은 결과를 본다. 내부 함수 구조나 쿼리 문자열은 검증하지 않는다.
- **주된 테스트 지점: 백엔드 HTTP 경계**: axum 라우터에 요청을 직접 보내고, DB는 Docker로 띄운 실제 Postgres를 쓴다. 다음을 모두 이 지점에서 검증한다.
  - 새 URL 생성과 같은 URL 재입력 시 기존 번호 반환
  - 검증 실패 각각(스킴, 호스트, 공백, 사용자 정보, 길이, 자기 단축 주소, 알 수 없는 필드)이 400으로 거부됨
  - 302 `Location`이 원본 URL과 정확히 같음(경로·쿼리·프래그먼트 포함), 단축 주소의 쿼리는 무시됨
  - 존재하지 않는 번호와 잘못된 번호 형식이 404 안내 화면을 돌려줌
  - PUT, PATCH, DELETE가 405로 거부됨
  - 서로 다른 URL을 동시에 여러 개 생성해도 번호가 겹치지 않고 기존 링크가 덮어써지지 않음, 같은 URL을 동시에 생성하면 번호가 하나만 생김
  - 같은 DB에 라우터를 새로 만들어도 이전 번호가 같은 원본 URL로 이동함(재시작 시뮬레이션)
  - SQL로 직접 시도한 UPDATE, DELETE, TRUNCATE가 트리거에 의해 거부됨
- URL 검증과 번호 해석은 별도 단위 테스트 없이 HTTP 경계를 통해 검증한다.
- **배포 후 점검 스크립트**: 배포된 공개 주소에 curl로 요청을 보내 확인 시나리오를 검사한다. 생성, Cloudflare 프록시를 거친 `/<번호>` 이동, 404, 405, 잘못된 URL 거부를 확인한다. Cloudflare Worker 프록시의 검증은 이 스크립트가 맡는다.
- **수동 확인**: Dioxus 화면(복사 버튼, 안내 문구)은 자동 테스트 없이 시크릿 창과 다른 브라우저에서 직접 확인한다.
- **기존 테스트 사례**: 저장소에 아직 코드가 없어 참고할 기존 테스트는 없다.

## Out of Scope

- 회원가입, 로그인, 링크 소유권
- 링크 수정, 삭제, 만료
- 사용자가 정하는 별칭, 영문·랜덤 문자열 경로
- 클릭 수 등 통계
- 요청 수 제한 등 남용 방지(필요해지면 Cloudflare 요청 제한 규칙으로 추가)
- 원본 URL 정규화(`https://a.com`과 `https://a.com/`은 다른 링크)
- 사용자 지정 도메인(`*.workers.dev` 사용)
- Railway 백엔드 직접 접근 차단
- Dioxus 화면과 Cloudflare Worker의 자동 테스트

## Further Notes

- 이 Mac에는 Rust, Dioxus CLI(`dx`), `wrangler`, `railway`가 아직 설치되어 있지 않다. 구현을 시작할 때 설치한다. Docker는 설치되어 있어 테스트용 Postgres에 쓴다.
- 프로젝트 폴더는 아직 git 저장소가 아니다. 배포 단계 전에 git 저장소와 공개 GitHub 저장소를 만든다.
- Railway, Cloudflare, GitHub 로그인과 연동 승인, Cloudflare API 토큰의 GitHub Secrets 등록은 사용자가 직접 한다.
- README는 한국어로 쓰고, 같은 원본 URL 재입력 규칙(기존 번호 반환), 실행 방법, 환경변수를 적는다.
- 용어는 GLOSSARY.md의 원본 URL, 번호, 단축 주소, 링크를 따른다.
